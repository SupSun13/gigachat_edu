# Telegram-боты на GigaChat: от прямого вызова до агента на Google ADK

Учебный проект: **два варианта** Telegram-бота с моделью GigaChat, от простого к сложному.

| | `bot.py` — прямой вызов | `agent_tg.py` — агент на ADK |
|---|---|---|
| Мозг | GigaChat напрямую через [LiteLLM](https://docs.litellm.ai/) | агент на [Google ADK](https://google.github.io/adk-docs/) |
| Память диалога | вручную: словарь `history` в коде | сессии ADK, автоматически |
| Инструменты | нет — только текст | function calling: погода ([Open-Meteo](https://open-meteo.com/)), текущее время |
| Зачем | показать механику: как «память» LLM собирается руками | показать агентный цикл: модель сама решает, когда звать функции |

Вместе они иллюстрируют главный тезис: **обвязка (Telegram) не зависит от мозга** — меняется ядро, мост остаётся тем же.

## Архитектура

Вариант 1 — прямой вызов:

```
пользователь → Telegram → bot.py (aiogram) → LiteLLM → GigaChat
                              │
                              └─ history: {chat_id: [сообщения]} — память вручную
```

Вариант 2 — агент:

```
пользователь → Telegram → agent_tg.py (aiogram) → ADK Runner → GigaChat
                                                       │
                                                       ├─ get_weather()      → Open-Meteo API
                                                       ├─ get_current_time()
                                                       └─ сессии ADK — память диалога
```

## Структура

```
.
├── bot.py                 # Вариант 1: Telegram + GigaChat напрямую
├── agent_tg.py            # Вариант 2: Telegram + агент на ADK

```

## Требования

- Python 3.10+
- Ключ GigaChat API (физлицам — бесплатный пакет токенов)
- Токен Telegram-бота

## Установка

```bash
git clone https://github.com/USERNAME/REPO.git
cd REPO

python -m venv venv
source venv/bin/activate        # Linux / macOS
# source venv/Scripts/activate  # Windows (Git Bash)

pip install google-adk litellm aiogram requests python-dotenv
pip install -U litellm          # нужна свежая версия с поддержкой GigaChat
```

Для одного только `bot.py` хватило бы `litellm + aiogram + python-dotenv`, но одна установка покрывает оба варианта.

## Ключи

**GigaChat.** Зарегистрируйся на [developers.sber.ru](https://developers.sber.ru/) (вход через Сбер ID), создай проект **GigaChat API** и получи **Authorization Key** — длинную base64-строку. Скоуп для физлица — `GIGACHAT_API_PERS`.

**Telegram.** Найди в Telegram бота [@BotFather](https://t.me/BotFather), команда `/newbot` → задай имя и username (должен кончаться на `bot`). В ответ придёт токен вида `1234567890:AAE...`.

Создай файл `.env` в **корне проекта**:

```
GIGACHAT_CREDENTIALS=твоя_base64_строка_целиком
TELEGRAM_BOT_TOKEN=1234567890:AAE...
```

> **Не коммить `.env`!** Файл должен быть в `.gitignore`. Ключ, попавший в публичный репозиторий, считается скомпрометированным — его нужно отозвать и создать новый.

> **Один токен — один запущенный бот.** Оба варианта используют один `TELEGRAM_BOT_TOKEN`, поэтому запускай их **по очереди**, не одновременно — иначе Telegram выдаст ошибку `Conflict`. Хочешь гонять оба параллельно — создай у BotFather второго бота и используй два токена.

## Вариант 1: `python bot.py`

Простой чат-бот с памятью диалога. Что попробовать:

- «Меня зовут Серёжа» → затем «Как меня зовут?» — помнит: история диалога отправляется модели целиком при каждом запросе
- `/reset` → «Как меня зовут?» — уже не помнит: память очищена
- `/start` — начать заново

Как устроена память: словарь `history` хранит список сообщений `{"role": "user"/"assistant", "content": ...}` для каждого чата. Модель сама по себе ничего не помнит — каждый запрос она перечитывает диалог с нуля. Отправляются только последние 20 реплик (`MAX_TURNS`) — защита контекста и квоты токенов.

## Вариант 2: `python agent_tg.py`

Агент с инструментами и сессиями ADK. Что попробовать:

- «Какая погода в Казани?» — агент вызовет `get_weather`, координаты определит сам (в чате появится уведомление о вызове инструмента)
- «Сколько сейчас времени?» — вызовет `get_current_time`
- «А в Питере?» — сработает память сессии: агент поймёт контекст из истории
- «Привет!» — ответит сам, без инструментов: модель решает, нужен ли вызов
- `/reset` — очистить память диалога

Каждый Telegram-чат получает свою сессию ADK — история хранится автоматически, пользователи изолированы. Сравни с вариантом 1: словаря `history` в коде больше нет, эту работу делает ADK.

В обоих вариантах скрипт молча висит в терминале — это нормально: крутится цикл polling. Остановить — `Ctrl+C`.

## Отладка агента через adk web

Агента из варианта 2 можно запустить в веб-интерфейсе ADK с трейсами всех вызовов инструментов:

```bash
adk web
```

Открой [http://localhost:8000](http://localhost:8000) и выбери `gigachat_agent`. Видно, какие аргументы модель передала в функцию. К варианту 1 это не относится — там нет ADK.

## Частые ошибки

**`TokenValidationError: Token is invalid! ... NoneType`** — бот не нашёл `TELEGRAM_BOT_TOKEN`: файла `.env` нет в корне, строка с токеном отсутствует, или есть пробелы вокруг `=` (нельзя: только `КЛЮЧ=значение` впритык).

**`Conflict: terminated by other getUpdates request`** — с одним токеном запущены два процесса: две копии одного бота или оба варианта сразу. Telegram разрешает только один polling на токен — останови лишний процесс.

**`SSL: CERTIFICATE_VERIFY_FAILED`** — GigaChat API работает на сертификатах НУЦ Минцифры, которых нет в стандартных хранилищах. В коде стоит `ssl_verify=False` — для учебного демо это допустимо. Правильный путь для продакшена — установить сертификаты Минцифры и убрать флаг.

**`401 Unauthorized`** — в `.env` вставлен не тот ключ: нужен **Authorization Key** целиком (base64-строка), а не client_id или client_secret по отдельности.

**Первый ответ агента приходит с задержкой** — норма для варианта 2: внутри два обращения к GigaChat (решение о вызове инструмента → финальный ответ) плюс запрос к Open-Meteo.

## Ограничения

- Память живёт в RAM в обоих вариантах (словарь / `InMemoryRunner`): перезапустил скрипт — диалоги забыты.
- Бот работает, пока запущен скрипт (polling). Для постоянной работы нужен сервер.
- Лимит Telegram — 4096 символов на сообщение: очень длинный ответ модели в варианте 1 может не отправиться.
- Встроенные инструменты ADK (например, `google_search`) работают только с Gemini — с GigaChat используются свои функции, как в этом проекте.
- Модель задаётся в коде (`gigachat/GigaChat-2`). Список доступных моделей зависит от тарифа — можно поменять на `GigaChat-2-Max` и другие; у старших моделей вызов инструментов стабильнее.
